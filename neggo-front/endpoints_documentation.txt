# Neggo API Endpoints Documentation

This document lists the endpoints called by the frontend and the expected structure of the `data` field in the response.

## Standard Response Format
All responses from the backend should follow this structure:
```json
{
  "success": boolean,
  "error": string | null,
  "data": any
}
```

---

## 1. Authentication

### POST `/auth/login`
- **Purpose**: Authenticate user.
- **Payload**: `{ email, password }`
- **Data on Success**: 
  ```json
  {
    "id": "user_uuid",
    "token": "session_jwt_string",
    "chatToken": "custom_firebase_token_for_chat",
    "user": {
      "id": "string",
      "name": "string",
      "photoUrl": "string",
      "rating": "number",
      "isPro": "boolean",
      "plan": "string"
    }
  }
  ```

### POST `/auth/register`
- **Purpose**: Create a new account.
- **Payload**: `{ email, password, name, phone }`
- **Data on Success**: `null` (Redirects to login page)

---

## 2. Advertisements (Offers)

### GET `/ads`
- **Purpose**: Fetch all active ads.
- **Data on Success**: `Ad[]` (List of Ad objects)

### GET `/ads/:id`
- **Purpose**: Fetch details of a specific ad.
- **Data on Success**: `Ad` (Single Ad object)

### POST `/ads`
- **Purpose**: Create a new ad.
- **Payload**: `Partial<Ad>`
- **Data on Success**: `Ad` (The created Ad object)

---

## 3. Chat System (Now integrated into Backend)

### GET `/chats`
- **Purpose**: Fetch all active conversations for the user.
- **Data on Success**: `ChatListItem[]`

### POST `/ads/:id/chat`
- **Purpose**: Start or retrieve a chat for a specific ad.
- **Data on Success**: `{ id: string }` (The chat room ID)

### GET `/chats/:id/messages`
- **Purpose**: Fetch messages for a specific conversation.
- **Data on Success**: `Message[]`

### POST `/chats/:id/messages`
- **Purpose**: Send a message.
- **Payload**: `{ text: string }`
- **Data on Success**: `Message`

---

## 4. Plans and Subscriptions

### GET `/plans`
- **Purpose**: Fetch all available subscription plans.
- **Data on Success**: `Plan[]`

### POST `/plans/:id/buy`
- **Purpose**: Purchase a subscription plan.
- **Data on Success**: `{ success: true, checkoutUrl?: string }`

---

## 5. Boosts

### POST `/ads/:id/boost`
- **Purpose**: Purchase a visibility boost for a specific ad.
- **Data on Success**: `{ success: true, checkoutUrl?: string }`

---

## 6. Profile

### GET `/profile`
- **Purpose**: Fetch current user profile details.
- **Data on Success**: `User` (User profile object)

### PUT `/profile`
- **Purpose**: Update current user profile or preferences.
- **Payload**: `Partial<User>` (e.g., `{ preferences: { contactMode: 'chat' } }`)
- **Data on Success**: `User` (Updated profile object)

---

## 7. User Specific Lists (Private)
All endpoints below REQUIRE the `Authorization: Bearer <token>` header.

### GET `/my-ads`
- **Purpose**: Fetch ads created by the current authenticated user.
- **Expected Data**: `Ad[]`

### GET `/favorites`
- **Purpose**: Fetch ads favorited by the current user.
- **Expected Data**: `Ad[]`

### POST `/ads/:id/favorite`
- **Purpose**: Toggle favorite status for an ad.
- **Data on Success**: `null`

---

## Data Models

### Ad Object
```json
{
  "id": "string",
  "title": "string",
  "description": "string",
  "price": "number | 'negotiable'",
  "isNational": "boolean",
  "locations": [{ "city": "string", "state": "string" }],
  "type": "'product' | 'service'",
  "category": "string",
  "images": ["string"],
  "sellerId": "string",
  "condition": "'new' | 'used'",
  "serviceType": "'remote' | 'in_person'",
  "isBoosted": "boolean",
  "status": "'active' | 'sold' | 'cancelled'",
  "createdAt": "ISO_DATE_STRING"
}
```

### User Object
```json
{
  "id": "string",
  "name": "string",
  "photoUrl": "string",
  "rating": "number",
  "isPro": "boolean",
  "phone": "string",
  "plan": "string",
  "preferences": {
    "contactMode": "'chat' | 'both'",
    "showPhoto": "boolean"
  }
}
```

### Plan Object
```json
{
  "id": "string",
  "name": "string",
  "price": "number",
  "adLimit": "number",
  "benefits": ["string"]
}
```
